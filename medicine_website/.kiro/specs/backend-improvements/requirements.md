# Requirements Document

## Introduction

This specification addresses two critical backend improvements for the Medicine Assistant application: unifying the drug interaction check logic across logged-in and non-logged-in flows, and implementing conversational intelligence in the chatbot to distinguish between casual conversation and medical queries.

## Glossary

- **GNN_Model**: Graph Neural Network model used for predicting drug interaction risks
- **RAG_System**: Retrieval-Augmented Generation system that looks up drug interaction data
- **Quick_Check**: The drug interaction check feature available to non-logged-in users on the landing page
- **Emergency_Check**: The drug interaction check feature available to logged-in users on the dashboard
- **Chatbot**: The AI assistant interface that responds to user messages
- **Intent_Classifier**: Component that determines whether a user message is conversational or medical
- **Interaction_Engine**: The unified backend service that processes drug interaction queries using GNN, RAG, and LLM
- **Risk_Score**: Numerical value (0-100) indicating the severity of drug interactions

## Requirements

### Requirement 1: Unified Drug Interaction Analysis

**User Story:** As a user (logged-in or not), I want consistent and accurate drug interaction analysis, so that I receive the same quality of risk assessment regardless of how I access the feature.

#### Acceptance Criteria

1. WHEN a user submits drugs through Quick_Check, THEN THE Interaction_Engine SHALL process the request using GNN_Model, RAG_System, and LLM analysis
2. WHEN a user submits drugs through Emergency_Check, THEN THE Interaction_Engine SHALL process the request using the same GNN_Model, RAG_System, and LLM analysis
3. WHEN the Interaction_Engine processes any drug query, THEN THE System SHALL return a Risk_Score between 0 and 100
4. WHEN the Interaction_Engine processes any drug query, THEN THE System SHALL return a detailed explanation generated by the LLM
5. WHEN the Interaction_Engine processes any drug query, THEN THE System SHALL return interaction data retrieved from RAG_System

### Requirement 2: Consolidated Backend Endpoint

**User Story:** As a developer, I want a single backend endpoint for drug interaction analysis, so that the codebase is maintainable and consistent.

#### Acceptance Criteria

1. THE System SHALL provide a unified API endpoint for drug interaction analysis
2. WHEN the unified endpoint receives a drug list, THEN THE System SHALL invoke GNN_Model for risk prediction
3. WHEN the unified endpoint receives a drug list, THEN THE System SHALL query RAG_System for interaction data
4. WHEN the unified endpoint receives a drug list, THEN THE System SHALL generate an LLM explanation combining GNN and RAG results
5. WHEN the unified endpoint completes processing, THEN THE System SHALL return a structured response containing risk_score, explanation, and interaction_details

### Requirement 3: Chatbot Intent Classification

**User Story:** As a user, I want the chatbot to understand when I'm making casual conversation versus asking medical questions, so that I can interact naturally with the assistant.

#### Acceptance Criteria

1. WHEN a user sends a conversational message (greetings, small talk), THEN THE Intent_Classifier SHALL identify it as conversational intent
2. WHEN a user sends a medical query (drug names, symptoms, interactions), THEN THE Intent_Classifier SHALL identify it as medical intent
3. WHEN the Intent_Classifier identifies conversational intent, THEN THE Chatbot SHALL respond with appropriate conversational replies
4. WHEN the Intent_Classifier identifies medical intent, THEN THE Chatbot SHALL invoke the Interaction_Engine
5. WHEN a message contains both conversational and medical elements, THEN THE Intent_Classifier SHALL prioritize medical intent

### Requirement 4: Conversational Chatbot Responses

**User Story:** As a user, I want the chatbot to respond naturally to greetings and casual messages, so that the interaction feels human and welcoming.

#### Acceptance Criteria

1. WHEN a user sends a greeting (hi, hello, hey), THEN THE Chatbot SHALL respond with a welcoming message and offer assistance
2. WHEN a user asks "how are you", THEN THE Chatbot SHALL respond conversationally and redirect to medical assistance
3. WHEN a user sends a thank you message, THEN THE Chatbot SHALL acknowledge and offer further help
4. WHEN a user sends goodbye, THEN THE Chatbot SHALL respond with a closing message
5. WHEN a user sends an unclear message, THEN THE Chatbot SHALL ask for clarification about their needs

### Requirement 5: Medical Query Processing

**User Story:** As a user asking medical questions, I want the chatbot to extract drug names and analyze interactions, so that I receive accurate health information.

#### Acceptance Criteria

1. WHEN the Chatbot receives a medical intent message, THEN THE System SHALL extract drug names from the message
2. WHEN drug names are extracted, THEN THE Chatbot SHALL invoke the Interaction_Engine with the extracted drugs
3. WHEN the Interaction_Engine returns results, THEN THE Chatbot SHALL format the response with risk information and explanations
4. WHEN no drug names can be extracted, THEN THE Chatbot SHALL ask the user to specify drug names
5. WHEN only one drug is mentioned, THEN THE Chatbot SHALL provide information about that single drug

### Requirement 6: Error Handling and Edge Cases

**User Story:** As a user, I want the system to handle errors gracefully, so that I always receive helpful feedback even when something goes wrong.

#### Acceptance Criteria

1. WHEN the GNN_Model fails to load or process, THEN THE System SHALL log the error and return a fallback response
2. WHEN the RAG_System cannot find interaction data, THEN THE System SHALL indicate limited information availability
3. WHEN the LLM service is unavailable, THEN THE System SHALL return GNN and RAG results without LLM explanation
4. WHEN invalid drug names are provided, THEN THE System SHALL inform the user and request valid drug names
5. WHEN the Interaction_Engine times out, THEN THE System SHALL return a timeout error with retry instructions

### Requirement 7: Response Consistency

**User Story:** As a user, I want to receive consistently formatted responses, so that I can easily understand the risk information regardless of which feature I use.

#### Acceptance Criteria

1. WHEN any interaction analysis completes, THEN THE System SHALL return results in a standardized JSON format
2. THE standardized format SHALL include fields for risk_score, severity_level, explanation, interactions, and recommendations
3. WHEN displaying results in Quick_Check, THEN THE Frontend SHALL use the same components as Emergency_Check
4. WHEN displaying results in the Chatbot, THEN THE System SHALL format the standardized response into conversational text
5. WHEN an error occurs, THEN THE System SHALL return errors in a standardized error format

### Requirement 8: Performance and Reliability

**User Story:** As a user, I want fast and reliable responses, so that I can quickly assess drug safety.

#### Acceptance Criteria

1. WHEN processing a drug interaction query, THEN THE Interaction_Engine SHALL respond within 5 seconds under normal conditions
2. WHEN the GNN_Model is loaded, THEN THE System SHALL cache it in memory for subsequent requests
3. WHEN multiple users query simultaneously, THEN THE System SHALL handle concurrent requests without degradation
4. WHEN the system starts, THEN THE System SHALL pre-load the GNN_Model and RAG_System
5. WHEN a component fails, THEN THE System SHALL continue operating with degraded functionality rather than complete failure
